# جدولة استبيانات الفروع

توضع الجدولة داخل وثيقة الاستبيان في مجموعة `surveys`:

```json
{
  "status": "active",
  "targetBranchIds": ["branch-id"],
  "schedule": {
    "type": "weekly",
    "startDate": "2026-10-09",
    "weekDay": 1,
    "timezone": "Asia/Riyadh",
    "missedPolicy": "latest_only"
  }
}
```

- `type`: إحدى القيم `daily` و`weekly` و`month_start` و`month_end`.
- `startDate`: أول تاريخ مسموح به بصيغة `YYYY-MM-DD`. لا يظهر الاستبيان قبل هذا التاريخ.
- `weekDay`: مطلوب للأسبوعي فقط؛ الاثنين `1` حتى الأحد `7`. إذا لم يوافق `startDate` اليوم المختار، يكون أول موعد في أول يوم مطابق بعده.
- `timezone`: منطقة زمنية معرّفة وفق IANA؛ يُحسب بدء اليوم بها، لا بوقت جهاز المستخدم.
- `missedPolicy`: القيمة المدعومة حاليًا `latest_only`؛ يُطلب آخر موعد مستحق فقط، ويبقى مطلوبًا حتى الإرسال أو يحل موعد أحدث مكانه.

تُحفظ الإجابة في `surveyResponses` بمعرّف `surveyId__branchId__YYYY-MM-DD` وحقل `occurrenceDate`. المسودة مرتبطة بالموعد نفسه. عند فتح موعد جديد يُستعاد آخر استبيان **مرسل** للفرع والاستبيان، إن وجد، مع تنبيه للمستخدم. المسودات القديمة لا تُنسخ تلقائيًا.

الاستبيانات القديمة التي تحتوي `startsFrom: "YYYY-MM"` من دون `schedule` تظل تعمل بنهاية الشهر وتوقيت `Asia/Aden`. تُقرأ الإجابات الشهرية القديمة المحفوظة بمعرّف `surveyId__branchId__YYYY-MM` حتى لا يُعاد طلب إجابة مرسلة.

يتحقق الحارس عند دخول الفرع. وإذا بقيت صفحة الفرع مفتوحة، يُعاد التحقق عند العودة للتبويب وكل خمس دقائق وهو ظاهر. دخول الإدارة إلى الفرع معفى من شرط الاستبيان.

## الوثائق الصحية

نوع السؤال `health_documents` يحفظ مصفوفة `workers` داخل `answers[questionId]`، مع إمكان إضافة أكثر من عامل. سؤال `document` القديم الذي يحمل عنوان وثائق صحية أو معرفًا يحوي `health_documents` يُعرض بالنموذج نفسه للتوافق. يلزم عامل واحد مكتمل على الأقل عند إرسال سؤال مطلوب؛ أما المسودة فيمكن حفظها قبل الاكتمال.
