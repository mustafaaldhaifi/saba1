# هيكلة التطبيق المستهدفة

يُنظَّم التطبيق حسب الميزة (feature) وليس حسب نوع الملف. تبقى الملفات المشتركة والبنية التحتية فقط في `core` و`shared`.

```text
app/
├─ core/
│  ├─ auth/                 # الجلسة، المستخدم الحالي، Guards
│  ├─ firebase/             # تهيئة Firebase المشتركة
│  └─ storage/              # الكاش والتخزين المحلي
├─ shared/
│  └─ dialogs/              # نوافذ التأكيد وإدخال السبب
└─ features/
   ├─ branches/             # صفحة الفرع ومكوّناتها وبيانات الفروع
   ├─ orders/               # الطلبات وأنواعها وعملياتها
   ├─ inventory/            # حسابات المخزون وقواعد الكميات
   ├─ reports/              # التقارير والتصدير إلى PDF وExcel
   └─ dashboard/            # لوحة الإدارة
```

## قواعد النقل

1. تُنقل ميزة واحدة في كل مرة مع ملفاتها (المكوّن والقالب والنمط والاختبار والخدمات القريبة).
2. لا تتغير المسارات أو سلوك المستخدم خلال النقل.
3. أي عملية تقرأ أو تعدّل Firestore أو التخزين المحلي توثّق بجانب الميزة قبل تنفيذها.
4. لا تُنشأ مجلدات عامة مثل `services` أو `components` لكل التطبيق؛ الملف يوضع قرب الميزة التي تستخدمه.
5. `core` للخدمات الوحيدة المشتركة على مستوى التطبيق، و`shared` للمكونات المرئية المشتركة فقط.
